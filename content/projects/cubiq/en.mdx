# Cubiq

## The problem

Most serious speedcubers still time their solves in csTimer. It works, but it looks and feels like 2008, and it stops at timing. There was no modern tool that combined a pleasant training screen with proper statistics and help with solving.

I wanted one place to train, track progress, and ask "how should this scramble have been solved?" for any puzzle, from the 2×2 to the Square-1. Cubiq is built for intermediate and advanced cubers who time themselves on several puzzles and care about their averages.

## What I built

### A timer that stays exact

The clock reads the browser's high-resolution time on every frame, so a long solve never drifts. A 300-millisecond hold arms the timer, the same way competition inspection works. Averages follow the World Cube Association rules, from ao5 up to ao100.

### A separate solver for each puzzle

I wrote a solver for each of the eight major puzzles and picked the strategy by how many positions the puzzle has.

- **2×2, Pyraminx and Skewb** are small enough to precompute every position. The solver looks up the shortest solution, which is never longer than 11 moves.
- **3×3** is solved the way people solve it (CFOP). It finds an optimal cross, pairs up the first two layers, and recognises every last-layer case from a full algorithm set. Wasted moves between stages are cancelled.
- **4×4 and 5×5** are reduced to a 3×3 by solving the centres and pairing the edges, with parity fixes, then finished by the 3×3 solver.
- **Megaminx** is solved layer by layer, with a small library of move sequences for the last layer.
- **Square-1** needs two phases: first restore the shape, then the pieces. I also built a 3D view that animates its half-turn flips as solid geometry.

### A model that teaches itself to solve the cube

A separate Python service trains a neural network the way DeepCubeA did. It scrambles a solved cube, then learns to estimate how many moves it is from solved. A research dashboard shows training live. You can run the model on a scramble and compare its answer with the optimal one from Kociemba's solver, which I use only as a benchmark.

### One workspace for every puzzle

The solvers page has a tab per puzzle and keeps each scramble when you switch between them. After a timed solve, "Solve this" opens the matching solver with your scramble already filled in.

## Result

Cubiq is live and free to use. It solves all eight puzzles with solvers I wrote myself. I used cubing.js only to draw the cube and scramble it, and Kociemba's solver only to measure against. Every solve is saved in the browser and can be exported. The first plan only had a cross solver, marked as possibly too hard for an early phase. I built Cubiq in about 11 weeks, from May to July 2026.

## Under the hood

- cubing.js's `TwistyPlayer` references `self` at module load, so it's loaded with `dynamic(() => import(...), { ssr: false })` and mounted with `document.createElement('twisty-player')` inside a `useEffect`.
- Turbopack broke the URLs cubing.js uses to start its Web Workers. Switching the build to Webpack unblocked it.
- The timer renders `performance.now() - startTime`. `setInterval` only triggers re-renders and never measures time.
- 2×2, Pyraminx and Skewb use full God's-algorithm distance tables (up to ~3.1M positions). 3×3 uses IDA* for cross, x-cross and double x-cross, an F2L pair search, and an OLL/PLL database, with move cancellation across stage boundaries.
- 4×4 and 5×5 use geometry-generated move tables. The 5×5 needed a new cross-swap macro derived by conjugation to handle one parity case.
- Square-1 uses shape BFS, then exact piece descent. Its custom 3D view renders the puzzle as a double-sided shell and animates 180° equator flips as rigid geometry.
- The `cubiq-ml` FastAPI service uses Autodidactic Iteration and a dual-head ResNet: a value head for moves remaining and a policy head over 18 moves. Greedy and MCTS rollouts are available. The dashboard polls training status every two seconds.
- State lives in Zustand, persisted to localStorage with `skipHydration` to avoid SSR mismatches. Solves export and import as JSON. Deep links use `/solvers?puzzle=<id>&scramble=<alg>`.
- 19 solver API endpoints, about 13,700 lines split between TypeScript and Python, 70 commits.
